# seo-plugin

Плагин `seo-audit` для Claude Code: еженедельный технический SEO-аудит сайта с отчётом — что поправить, где, как и на что это повлияет.

**Статус: все проверки реализованы.** Не сделаны доставка отчёта (issue, Slack) и workflow для запуска по расписанию. Сборщики CrUX и Search Console написаны, но на живых API не проверялись: для них нужны ключи.

## Принцип

Работа делится на две фазы:

1. **Сбор и оценка — скрипты, без LLM.** Собирают метрики, применяют правила, сравнивают с прошлым запуском. Одинаковый вход даёт одинаковые находки.
2. **Разбор — Claude.** Находит причину в коде, пишет, как исправить и на что это повлияет.

Все числа в отчёте берутся из результатов скриптов. Сборщик, который не отработал, показывается как непокрытый, а не как «всё в порядке».

## Что проверяется

| Группа | Проверки | Сборщик |
|---|---|---|
| Доступность | HTTPS и сертификат, коды ответа, редиректы, `robots.txt`, sitemap, мягкие 404 | `http` |
| Индексация | canonical, meta robots, `X-Robots-Tag`, hreflang, дубли | `http` |
| On-page | title, description, h1, alt, Open Graph, битые ссылки, страницы-сироты | `http` |
| Разметка | JSON-LD парсится, есть обязательные для Google поля | `http` |
| Доступность для LLM | Политика для AI-ботов в `robots.txt`, реальный ответ ботам, текст в сыром HTML, `llms.txt` | `http` |
| Рендеринг | Страница открывается, нет JS-ошибок и упавших запросов, сырой HTML против DOM после JS | `browser` |
| Accessibility | Нарушения WCAG 2.1 A и AA по axe-core | `browser` |
| Скорость, лаб. | Lighthouse на ключевых страницах, медиана нескольких прогонов | `lab` |
| Скорость, поле | Core Web Vitals реальных пользователей из Chrome UX Report | `field` |
| Поиск | Клики неделя к неделе, статус ключевых страниц в индексе, ошибки sitemap | `search` |

Каждая находка получает статус относительно прошлого запуска: новая, ухудшилась, без изменений, исправлена.

Вне рамок: ключевые слова, контент-стратегия, ссылки, конкуренты, генерация текстов, автоправки.

## Что нужно сборщикам

| Сборщик | Что нужно | Если этого нет |
|---|---|---|
| `http` | ничего | работает всегда |
| `browser` | Chrome; `CHROME_PATH`, если он не в стандартном месте | рендеринг и accessibility не проверяются |
| `lab` | Chrome и `npx` | лабораторная скорость не проверяется |
| `field` | `GOOGLE_API_KEY` с включённым Chrome UX Report API | данные реальных пользователей не проверяются |
| `search` | `searchConsole.property` в конфиге и `GSC_SERVICE_ACCOUNT_KEY`; сервисный аккаунт добавлен в property | индекс и поисковый трафик не проверяются |

Ключи берутся только из переменных окружения, в конфиг они не пишутся.

## Установка

```bash
claude plugin marketplace add lebeDEV02/seo-plugin
```

```bash
claude plugin install seo-audit@seo-plugin
```

Скиллы:

- `/seo-audit:setup` — подключить проект: создать конфиг, проверить, какие сборщики здесь доступны, снять первый снимок;
- `/seo-audit:audit` — прогнать аудит и получить отчёт.

Плагин подключает MCP-сервер Chrome DevTools: скилл использует его, чтобы разобрать причину найденной проблемы со скоростью или рендерингом.

## Запуск без Claude

Сбор и оценка — обычный скрипт на Node 22+:

```bash
cd plugins/seo-audit && npm ci
```

```bash
node plugins/seo-audit/scripts/cli.mjs run --config seo-audit.config.json
```

Минимальный конфиг — `{ "site": "https://example.com" }`; все параметры описаны в `plugins/seo-audit/templates/seo-audit.config.json` и `schema/config.schema.json`.

Полный запуск занимает 10–20 минут, почти всё время уходит на Lighthouse. Ключ `--skip browser,lab,field,search` отключает сборщики: с `--skip lab` запуск укладывается в несколько минут.

Результат ложится в `.seo-audit/`:

- `runs/<время>/findings.json` — находки, покрытие, сравнение с прошлым запуском;
- `runs/<время>/raw/` — собранные факты;
- `history/` — снимки запусков, с которыми сравнивается следующий.

## Разработка

Плагин можно подключить из локальной папки без публикации:

```bash
claude --plugin-dir ./plugins/seo-audit
```

Проверка манифестов:

```bash
claude plugin validate .
```

Тесты:

```bash
cd plugins/seo-audit && npm test
```

## Структура

```
.claude-plugin/marketplace.json
plugins/seo-audit/
├── .claude-plugin/plugin.json
├── .mcp.json               # Chrome DevTools MCP
├── skills/                 # audit, setup
├── scripts/
│   ├── cli.mjs             # run: сбор, оценка, сравнение, запись результата
│   ├── collect/            # site, pages, browser, performance, search-console
│   ├── evaluate/           # каталог правил, правила, сравнение запусков
│   └── lib/                # http, robots, sitemap, html, config
├── rules/                  # AI-боты; обязательные поля разметки по документации Google
├── schema/                 # схема конфига
├── templates/              # пример конфига
└── test/
```

Файлы в `rules/` несут дату сверки: список AI-ботов и требования Google к разметке меняются, их нужно периодически пересматривать.
